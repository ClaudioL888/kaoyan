# 数二轻量三系统存储协议

## 预建骨架状态

知识库可预先包含 `organization_status: skeleton` 的章节目录。骨架只用于路由，不能作为已整理内容、覆盖率或验收证据。阶段二开始时可直接使用该目录，但不得把骨架中的占位文本当作阶段一来源。

只有完整第一版已被用户确认准确并同意归档、完整正文已保存、三系统提炼完成且覆盖检查通过，才能把目标章节改为 `organized`。局部批次、单题问答或 `confirmed_increment_count` 大于零都不足以升级；跨章复盘只更新真正达到上述条件的章节。

## 目录

知识库根目录固定为：

`E:\桌面\学习\考研\学习知识库\math2`

```text
math2/
├─ catalog.json
├─ calculus/
└─ linear-algebra/
   └─ <chapter-slug>/
      ├─ chapter.json
      ├─ textbook_knowledge.md
      ├─ question_methods.md
      ├─ user_weaknesses.md
      └─ reviews/
         ├─ YYYY-MM-DD_HHmm_<scope-slug>.md
         └─ YYYY-MM-DD_HHmm_<scope-slug>.review-manifest.json
```

目录 slug 只使用小写英文字母、数字和连字符。正文、标题和关键词使用中文 UTF-8。

## catalog.json

保持以下最小结构：

```json
{
  "schema_version": "1.0",
  "subject": "math2",
  "updated_at": "2026-08-18T00:00:00+08:00",
  "chapters": [
    {
      "chapter_id": "math2.linear-algebra.ch05",
      "module": "linear-algebra",
      "title": "特征值与特征向量",
      "aliases": ["矩阵特征值", "相似对角化"],
      "keywords": ["特征值", "特征向量", "相似", "对角化"],
      "path": "linear-algebra/ch05-eigenvalues-eigenvectors",
      "updated_at": "2026-08-18T00:00:00+08:00"
    }
  ]
}
```

`chapters` 中每个 `chapter_id` 和 `path` 必须唯一。更新已有章节，不追加重复行。

## 三系统 Markdown

### textbook_knowledge.md

按知识点标题组织。每项只保留：结论或定义、成立条件、怎么理解、怎么用、易错边界、已核实来源页或“AI概括/推导”状态。不要复制整道题。

### question_methods.md

按题型标题组织。每项只保留：识别信号、第一反应、标准方法、适用条件、主要风险、代表题号和对应 review 文件。完整题面只存在于 `reviews/`。

### user_weaknesses.md

只记录真实用户证据。每项包含：日期、用户表现或原话、错误类型、正确边界、关联范围、建议复现动作。没有真实证据时保持文件只有标题和边界说明。

用户主动说出正确结论，不能据此写成“已掌握/不薄弱”，也不能直接写成薄弱点。应结合语气和上下文判断是否存在猜测、犹豫、自我纠正、反复确认、矛盾、依赖提示或无法解释；证据不充分时只在对话归纳中标记 `候选薄弱点（待确认）` 并向用户确认。候选状态不得落盘，确认后仍需重新展示归纳并取得准确性与归档双重确认。

## 派生条目的五态归并门

对阶段一成品派生出的每个教材知识、题型方法和真实个人弱点分别检索最相近旧条目，并按数学对象、结论、条件、识别信号、决定性步骤、边界、风险和代表题作用判定：

- **等价**：不新建；仅当新题是更典型的例题/反例或新增可靠来源时，给原条目补短引用和 `引用补充时间`，不登记新的知识活动。
- **补充**：直接扩充原条目的条件、步骤、边界、反例、风险或代表题，保留原记录时间，为增量写 `补充记录时间`、来源和题号。
- **相邻**：放入现有知识簇/方法池的父标题下作为子条目，并写短引用，不建立孤立题号标题。
- **冲突**：在最相关条目下并列旧结论、新结论、来源、日期、题号和待核验/采用状态，不覆盖旧内容。
- **全新**：确认没有合适簇后才新建可迁移的顶层条目。

无可迁移价值或无可靠证据时判 `无需新增`。跨章节只保留一个规范主条目，其他章节放短引用；不得完整复制。复核结果若与用户确认的预判在类别、目标或内容上有实质变化，先展示修订后的完整归纳并重新取得双重确认。

## 保存顺序

1. 确认用户已同时认可当前“阶段一完整第一版”及其末尾归纳的准确性，并明确同意归档；预检、提纲、答案表、局部摘要、单独的“准确”或单独的“保存”均不能替代这两个确认。
2. 生成唯一 review 文件名；若同分钟重名，追加 `-02`、`-03`，绝不覆盖旧稿。
3. 以已接受正文为阶段二的唯一内容母本。完整读取并执行 [review-artifact-protocol.md](review-artifact-protocol.md)：恢复单段或全部已验收传输段，先取得逐段规范化正文哈希，再按段序拼成一个 review Markdown，并生成相邻 `.review-manifest.json`。只去掉正文边界外的聊天寒暄；BEGIN/END 之间的正文不得删改，`拟沉淀内容` 即使不参与三系统归并也保留在 accepted review 中。写后验证逐段及 assembled 哈希；原文不可取得时停止并报告归档正文缺口，禁止摘要重建。
4. 创建或更新三个 Markdown 文件：
   - 对每个派生逻辑项执行上述五态归并，不机械复制；
   - 不因新整理删除旧内容；
   - 出现冲突时同时保留，标注日期、范围、来源状态与 `待核实`。
5. 更新 `chapter.json` 的资料、review 清单和时间。
6. 更新 `catalog.json` 的章节入口、关键词和时间。
7. 解析验证 chapter、catalog 与 review manifest 三类 JSON，检查 review、manifest 和三个系统文件均存在，再重新读取关键段落。
8. 向用户报告新增/更新文件、review 数量和未解决缺口。

阶段二不得重新扫描 PDF 另写一份替代成品，也不得从旧知识库、零散笔记或记忆重建当前 review。若已接受正文不在当前对话，先向用户索要正文或文件。

用户修正归纳、范围或结论时，必须先展示修订后的完整归纳并重新获得“准确性认可 + 归档授权”，修正本身不构成保存许可。

## 禁止事项

- 未确认时写入。
- 为知识点、题目、关系创建大规模原子 ID。
- 把通用高频错误写成用户个人薄弱点。
- 用新结果覆盖旧 review。
- 把未读取 PDF 的内容标记为教材原文或官方解析。

## 时间字段与活动日志

- review 正文和由其派生的每个实际新增逻辑条目都必须写实际归档时间：`记录时间：YYYY-MM-DD HH:mm:ss +08:00`；JSON 使用 ISO `recorded_at` 和 `time_zone: Asia/Shanghai`（中国标准时间）。
- 每份 review/addendum 追加一条 accepted-review 容器活动记录，并以 `derived_record_ids` 关联真实派生增量；每个派生 Markdown 条目自身写完整时间。
- 归档及派生写入全部验证后，向知识库根目录 `activity_log.jsonl` 登记 accepted review 和真正新增的知识/方法/薄弱点。每条保留章节、范围或题号、来源状态、源文件与简明摘要。
- 报告端必须能按 review/派生关系语义去重；不能把同一知识点因为同时存在于 review 和汇总文件而计算两次。
- 未确认、写入失败、已有等价内容和未落盘候选薄弱点不得进入活动日志。
- 等价条目仅补题号/review 引用时不登记派生知识活动；补充、相邻、冲突或全新形成实际逻辑增量时才登记，并只计本次增量，不把整个旧条目重新算作新增。
