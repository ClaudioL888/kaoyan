# 数二问答增量写入协议

## 触发边界

本协议只处理可供复习的数学内容：概念、定理、公式、条件、题目结论、解题方法、变式边界、真实错因。是否已保存、文件路径、覆盖数量、更新时间、任务进度、资料状态、skill 规则和知识库管理属于操作问题，直接回答，不展示待确认归纳，不邀请归档。混合问题只归纳数学部分。

## 回答末尾的强制归纳

每次数学课程内容回答必须以以下内容收尾：

```text
本次数学问题归纳（待确认，尚未保存）
- 你问的是：
- 核心结论：
- 识别信号：
- 标准方法：
- 成立条件与易错边界：
- 建议章节：
- 建议归档：教材知识 / 题型方法 / 个人薄弱点 / 无需新增 / 已有等价内容
- 归并判定（预判）：等价 / 补充 / 相邻 / 冲突 / 全新 / 无需新增
- 拟归并目标：已有条目标题 / 拟建父标题与子标题 / 新条目标题 / 无
- 拟写入内容：（无需新增写“无”；等价但拟补代表题/反例引用时写明引用，否则写“无”）
- 掌握度判断：当前掌握信号 / 候选薄弱点（待确认） / 已确认薄弱点 / 无法判断
- 用户证据：（仅个人薄弱点填写）

请确认：以上归纳是否准确，以及是否同意归入知识库？
如两项都同意，可回复“归纳准确，确认归入”。
```

准确性认可与归档授权缺一不可。用户修正归纳时，先重新展示完整修订版并再次等待双重确认。仅说“准确”或仅说“保存”均不直接写入。

## 用户主动结论与薄弱点判断

- 用户主动说出正确结论，只能证明本轮表述正确，不能自动记为“已掌握”“不薄弱”，也不能自动记为薄弱点。
- 有把握且能说明理由、条件和变式边界，可在本轮判断为“当前掌握信号”，但不把“非薄弱点”写进个人文件。
- “是不是/我感觉/可能/应该”、反复求确认、自相矛盾、“原来/我之前以为”、提示后才答对或说不清理由，属于候选薄弱信号。
- 证据不够时，在归纳中标为 `候选薄弱点（待确认）`，并询问用户这是已掌握后的总结，还是仍易混淆且希望记录的薄弱点。
- 用户确认前，不得写入 `user_weaknesses.md`；用户回答后必须更新完整归纳，再重新取得准确性认可与归档授权。

## 存储位置

使用 `E:\桌面\学习\考研\学习知识库\math2`，按 `catalog.json` 找到目标章节。章节目录固定包含：

```text
chapter.json
textbook_knowledge.md
question_methods.md
user_weaknesses.md
reviews/
```

完整章节成品由 `review-math-chapter` 归档；本 Skill 只追加经用户确认的新题型、方法和个人疑难点。

目录中允许存在 `organization_status: skeleton` 的预建章节。它只表示章名、别名、关键词和空文件已经创建，可用于路由；不得当作已有知识或章节完成证据。单题增量双重确认后写入对应文件，并将 `confirmed_increment_count` 加一，但继续保持 `skeleton`。只有 `review-math-chapter` 完成完整第一版、覆盖核对和归档后，才可改为 `organized`。

## 写入映射

- 定义、公式、条件、注意、推论、概念边界 → `textbook_knowledge.md`。
- 题型信号、第一反应、方法、变式、典型题、方法风险 → `question_methods.md`。
- 用户真实错误、犹豫、错误解法、反复追问或明确确认的薄弱点 → `user_weaknesses.md`。主动正确结论和候选薄弱点均不能直接写入。

不要把同一内容完整复制到三个文件；交叉关系用章节标题、题号或 review 路径的短说明表达，不建立关系 ID。

## 追加格式

每个新增条目使用清晰中文标题，并包含：

- `日期`；
- `范围/题号`；
- `来源状态`：教材核实、官方解析核实、独立推导、用户本题；
- `核心内容`；
- `适用条件或边界`；
- `下次复现动作`（若适用）。

个人薄弱点还必须保留用户证据，不能只写“容易错”。

## 相近内容五态归并门

该判定同时用于单题增量和章节复盘派生条目。写入前必须再次搜索目标章节及必要的相邻章节；比较数学对象、结论、成立条件、识别信号、核心变换/决定性步骤、适用边界、风险和代表题作用，不能只比标题、符号或题号。

1. **等价**：核心结论、条件和方法实质相同。不得新建条目；若本题是更典型的例题、反例或新来源，只在原条目补短题号/review 引用并写 `引用补充时间`，否则完全不写。引用补充不算新知识，不登记活动日志。
2. **补充**：同一知识点或题型方法，但本题增加了条件、边界、步骤、反例、风险或有价值的代表题。直接扩充原条目，保留原内容和原记录时间，新增部分标 `补充记录时间`、来源和题号；不得另起同级重复标题。
3. **相邻**：属于同一方法池/知识簇，但结论或适用边界不能合并成一条。放在现有父标题下建立子条目，并双向写短引用；不得创建孤立的顶层“某某题”。
4. **冲突**：答案、条件、定义口径或方法有效性不一致。不得强行合并或覆盖；在最相关条目下增加“冲突/待核实”块，并列旧结论、新结论、来源、日期、题号和采用状态。
5. **全新**：完成上述检索后确无合适知识簇或方法池，才允许新建顶层条目；标题应概括可迁移知识/方法，不以单道题号充当标题。

`无需新增` 不是归并状态：机械计算、无可迁移价值或无可靠证据时不写文件。一个问题若同时产生教材知识、题型方法和真实个人弱点，对三个逻辑项分别判定；个人弱点只能写在 `user_weaknesses.md`，可短链知识/方法但不能混入通用条目。跨章节已有更合适归宿时，选择一个规范主条目，只在当前章节放短引用，不完整复制。

回答末尾先给预判和拟归并目标。双重确认后的复核若改变分类、目标或拟写入内容，必须展示修订后的完整归纳并重新确认。任何归并都不得覆盖 `reviews/` 历史成品。

## 保存后检查

1. 确认用户的保存指令对应当前刚回答的题目或增量。
2. 只编辑目标章节的三个 Markdown 文件、`chapter.json` 和必要的 `catalog.json`。若目标是预建骨架，单题写入后只更新 `confirmed_increment_count` 和时间，不得把 `organization_status` 改成 `organized`，不得伪造 accepted review。
3. 验证 JSON 可解析、章节路径存在、没有重复 chapter path。
4. 重新读取新增标题和关键段落，确认没有把草稿、泛化判断或未核实原文写进去。
5. 报告写入文件和仍待核实的冲突；普通回答不主动展示这些路径。
6. 若建议为“无需新增”，不写入；若为“已有等价内容”，不得重复知识正文，只有归纳中已明确且确有代表价值时才补短题目/review 引用，否则只报告去重结果。
7. 报告实际归并状态、主条目标题、增加的题目引用/补充段落及跨条目短引用；不得只笼统报告“已保存”。

## 时间字段与活动日志

- 每个实际新增的逻辑条目必须包含 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`；`chapter.json` 或相关索引使用 ISO `recorded_at`，时区固定 `Asia/Shanghai`（中国标准时间）。
- 成功写入并复读通过后，向 `E:\桌面\学习\考研\学习知识库\activity_log.jsonl` 追加一行 JSON。必填 `record_id`、`recorded_at`、`record_date`、`time_zone`、`time_status=confirmed-archive`、`subject=math2`、`unit_id`、`record_type`、`title`、`summary`、`source_file`、`question_refs`、`source_status`。
- 一行只对应一个可独立理解的知识、方法或真实薄弱点；同一内容写入多个索引时只登记一次主记录，避免周期汇总重复计数。
- 等价条目仅补题目引用时，不增加 `confirmed_increment_count`，不登记活动日志；补充、相邻、冲突或全新形成实际逻辑增量时才按增量计数。
- 未写入、被去重、候选薄弱点或用户未完成双重确认时，不得追加时间记录。
