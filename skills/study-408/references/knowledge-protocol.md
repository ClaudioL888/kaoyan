# 408 单题知识库协议

## 预建章节骨架

数据结构、计算机组成原理、操作系统和计算机网络均按教材目录预建章节。`organization_status: skeleton` 只表示目录、别名、关键词和空文件存在，不能当作章节已有知识、已覆盖或已完成。

未整理章节的问题仍需正常回答：先读取当前题面和相关教材/解析，必要时独立推导并区分来源；末尾执行具体归纳与双重确认。确认后才可写入，并将 `confirmed_increment_count` 加一；章节继续保持 `skeleton`。只有完成该章的完整第一版、覆盖核对和正式归档后才可升级为 `organized`，单题、局部算法或少量增量均不够。

本协议只服务于课程内容类单题问答、错因诊断和可迁移方法增量，不能绕过章节级“完整第一版 → 验收 → 整理落盘”合同。管理、状态和 skill 规则问题不进入本协议的归档提醒环节。

## 归档提醒的触发边界

触发归档提醒的前提是，本轮回答产生了可供复习的 408 学科内容：概念或原理、题目结论、解题方法、复杂度分析、选项边界、易错规律，或者有真实证据的个人错因。

以下问题即使提到某一科目或知识库，也不触发“待确认”和归档询问：

- 是否已经写入、保存、完成或验收。
- 文件在哪里、有哪些文件、覆盖多少题、何时更新、当前进度如何。
- 资料是否存在、目录是否有效、JSON 是否可解析等检查结果。
- skill 是否触发、如何保存、确认口令是什么、知识库结构如何管理。
- 创建对话、安排任务、修改规范等操作性请求。

混合问题只归纳其中可独立复习的课程内容，不能把文件状态、任务进度或规则说明写进教材知识、题型方法或个人薄弱点。

## 读取顺序

1. 从题目识别科目、章节和知识点。
2. 读取该科目的 `catalog.json`，确认章节标识和实际路径。
3. 读取相关章节的 `textbook_knowledge.md`、`question_methods.md`、`user_weaknesses.md`。
4. 只有在需要比对既往完整题目、解法或用户作答时，才读取 `reviews/` 下的相关复盘。
5. 既有知识缺失、冲突或证据不足时，再回到本地教材、题册和官方解析核验。

## 强制结尾归纳

每次课程内容问答都必须在答案末尾展示以下内容，不以是否存在新增知识为条件。非课程内容问答不展示本块，也不询问是否归档：

```text
本次问题归纳（待确认，尚未保存）
- 你问的是：
- 核心结论：
- 建议章节：
- 建议归档：教材知识 / 题型方法 / 个人薄弱点 / 无需新增 / 已有等价内容
- 归并判定（预判）：等价 / 补充 / 相邻 / 冲突 / 全新 / 无需新增
- 拟归并目标：已有条目标题 / 拟建父标题与子标题 / 新条目标题 / 无
- 拟写入内容：（无需新增写“无”；等价但拟补代表题/反例引用时写明引用，否则写“无”）
- 适用条件或边界：
- 掌握度判断：当前掌握信号 / 候选薄弱点（待确认） / 已确认薄弱点 / 无法判断
- 用户证据：（仅建议归档为个人薄弱点时填写）

请确认：以上归纳是否准确，以及是否同意归入知识库？
如两项都同意，可回复“归纳准确，确认归入”。
```

知识库已有等价内容、只是在重复通用结论、机械计算且没有可迁移方法，或缺乏任何值得沉淀的新内容时，仍需完成归纳，但建议归档应标为“无需新增”或“已有等价内容”，不得为了满足格式制造条目。等价内容只有在当前题提供更典型过程、反例或可靠来源时才预判为“补短引用”。

## 用户主动结论与掌握度

- 用户主动说出正确结论，只能证明本轮表述正确，不能自动记为“已掌握/不薄弱”，也不能自动记为薄弱点。
- 能独立说明原理、条件、状态变化和变式边界，且语气明确，可视为本轮掌握信号，但不把“非薄弱点”写入个人文件。
- “是不是/我感觉/可能/应该”、反复求确认、自我纠正、前后矛盾、提示后才答对或无法解释算法/状态依据，属于候选薄弱信号。
- 证据不足时标记 `候选薄弱点（待确认）`，询问用户这是已掌握后的总结，还是仍易混淆并希望记录的薄弱点。
- 用户确认前不得写入 `user_weaknesses.md`；确认后先修订完整归纳，再重新取得准确性认可与归档授权。

## 三类落点

- 定义、机制、公式、性质、适用边界与易混概念 → `textbook_knowledge.md`
- 识别信号、解题流程、复杂度、状态变化、变式和风险 → `question_methods.md`
- 用户真实答错、犹豫、错误理由、错误方法、重复追问或明确确认的薄弱点 → `user_weaknesses.md`。主动正确结论和候选薄弱点均不能直接写入。

单题问答不新建章节复盘文件，也不改写既往 `reviews/`。个人薄弱点至少记录日期、题目或范围、用户证据、错误层级、正确边界和 24—48 小时复现动作。

## 确认与相近内容五态归并

1. 写入需要两个独立条件同时满足：用户认可当前归纳准确；用户明确同意把当前归纳归入知识库。可在同一条回复中同时确认。
2. 用户只说“准确”时，只完成准确性确认，不写入；只说“保存”但没有认可当前归纳时，先请求确认准确性。用户修改归纳时，输出修订后的完整归纳并重新等待两个确认。
3. 写入前再次读取目标文件及必要的相邻章节，不能只比标题或题号。数据结构比较算法模型、状态/不变量、操作和复杂度；计组比较字段/位宽、数据通路和时序；操作系统比较对象、队列/资源状态、PV/地址时间线；计网比较封装层次、地址、表项和逐跳行为。四科都要比较条件、步骤、结论、风险和错误模式。
4. **等价**：结论、条件和方法实质相同，不新建；仅当本题提供更典型状态过程、反例或可靠来源时，向原条目补短题号/review 引用和 `引用补充时间`。引用补充不算新知识，不登记活动日志。
5. **补充**：属于同一知识/方法但增加条件、状态步骤、复杂度/位宽/时序边界、反例或代表题，直接扩充原条目；保留原记录时间，新部分写 `补充记录时间`、来源和题号。
6. **相邻**：属于同一知识簇或方法池但不能合并为同一结论，放在已有父标题下建立子条目并短链相关项；不得新建孤立题号标题。
7. **冲突**：结论、复杂度、状态演化、位宽、协议行为或适用条件不一致，在最相关条目下并列旧/新结论、来源、日期、题号和待核验/采用状态，不擅自覆盖。
8. **全新**：确认本章及必要的相邻章节不存在合适知识簇/方法池后，才新建可迁移的顶层条目。
9. `无需新增` 用于机械计算、无迁移价值或证据不足；不写文件。跨章节/子科目存在规范主条目时，只保留一个主条目，其他位置用短引用，不完整复制。
10. 一个问题产生教材知识、题型方法和真实个人弱点时分别判定；个人弱点只能写入 `user_weaknesses.md`，相似的重复弱点应扩充原弱点记录并保留每次用户证据，而不能混入通用知识。
11. 用户只确认部分内容时，只保存被明确确认且归纳准确的部分。复核后类别、目标或拟写入内容发生实质变化时，先展示修订后的完整归纳并重新取得双重确认。
12. 不依据旧对话摘要、推测或模糊记忆补造未向用户展示的内容。

## 新科目或新章节

若目录尚不存在，先完成答疑并提出建议科目、章节和路径。用户认可归纳准确、同意归档并确认科目、章节和路径后，才建立最小结构：`catalog.json`、章节 `chapter.json`、三个知识文件和空 `reviews/` 目录。不得伪造来源、题号、官方表述或用户错误证据。

## 保存后检查

- JSON 可解析，章节标识唯一，目录中的路径真实存在。
- 复读目标文件，确认保存内容与用户认可准确并同意归档的归纳一致。
- 通用陷阱未被写成个人薄弱点。
- 未核验内容明确标为待核验，不冒充官方原文。
- 向用户报告实际修改文件、去重结果和仍待处理的冲突。
- 同时报告每个逻辑项的实际归并状态、主条目标题、追加的题目引用/补充段落及跨条目短引用。

## 时间字段与活动日志

- 每个实际新增逻辑条目写 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`，元数据写 ISO `recorded_at`，固定 `time_zone: Asia/Shanghai`（中国标准时间）。
- 写入与复读验证成功后，向 `E:\桌面\学习\考研\学习知识库\activity_log.jsonl` 追加一行，必填 `record_id`、时间、408 子科目、`unit_id`、记录类型、标题、摘要、源文件、题号/范围和来源状态。
- 数据结构的算法状态/复杂度、计组的位宽/信号通路、操作系统的进程/PV/地址时间线、计网的封装/地址/逐跳过程应进入摘要或题目例子，便于周期报告复现。
- 未双重确认、未成功落盘、语义去重无新增和候选薄弱点均不登记。
- 等价条目仅补题目引用时，不增加 `confirmed_increment_count`，不登记活动日志；补充、相邻、冲突或全新形成实际逻辑增量时才按增量计数。
