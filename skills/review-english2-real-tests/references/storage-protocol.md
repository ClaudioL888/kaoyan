# 英语二轻量知识库存储协议

## 固定目录

知识库根目录为 `E:\桌面\学习\考研\学习知识库\english2`：

```text
english2/
├─ catalog.json
├─ stable_rules.md
├─ user_weaknesses.md
└─ reviews/
   ├─ YYYY-MM-DD_HHmm_<year-part-scope>.md
   └─ YYYY-MM-DD_HHmm_<year-part-scope>.review-manifest.json
```

`catalog.json` 保存 `schema_version`、`subject`、`updated_at` 和 `accepted_reviews`。每条记录包含唯一 `review_id`、年份、题型、范围、相对路径、接受时间和实际使用的来源；不得登记未读取的资料。

此外，`modules/` 预建词汇、语法与长难句及六个真题题型模块。每个模块含 `module.json`、`evidence_and_language.md`、`answer_methods.md`、`user_weaknesses.md` 和 `reviews/`。`organization_status: skeleton` 只是可路由空骨架；`partially-organized` 只表示链接到跨模块 accepted review，二者都不能称为题型已完整整理。

## 单题课程内容增量

单题、单句、单个选项、翻译片段或作文局部问答可以在双重确认后直接增量更新汇总文件，不要求新建完整 review。回答末尾的归纳至少包含：年份/题型/题号或语句、原文证据状态、核心结论、定位/语言/排除/翻译/写作规则、适用边界、错因标签、建议归档类型、拟写入内容、`归并判定（预判）`和`拟归并目标`。

归纳还必须包含 `掌握度判断：当前掌握信号 / 候选薄弱点（待确认） / 已确认薄弱点 / 无法判断`。用户主动给出正确译法、选项或语言结论，只能证明本轮表述正确；不能自动写成“已掌握/不薄弱”，也不能直接写入个人薄弱点。结合是否有原文依据、理由、迁移边界，以及是否存在猜测、犹豫、自我纠正、反复确认、矛盾或提示依赖来判断。

证据不足时先询问这是已掌握后的总结，还是仍易混淆且希望记录的薄弱点。候选状态不得落盘；用户答复后先更新完整归纳，再重新取得准确性认可和归档授权。

只有用户同时认可归纳准确并同意归档才可写入。只确认准确、只说保存、修改归纳、继续讨论或沉默均不写入；修正后应重新展示完整归纳并再次确认。

- 原文证据、词汇、搭配、句法和篇章逻辑 → 命中模块的 `evidence_and_language.md`。
- 定位、同义替换、干扰项排除、翻译处理和写作组织 → 命中模块的 `answer_methods.md`。
- 有真实作答证据的错误、犹豫、错误理由或用户明确确认的薄弱点 → `user_weaknesses.md`。主动正确结论和候选薄弱点均不能直接写入。
- 无新增价值 → 不写入；已有等价内容不重复知识正文，只有当前真题提供更典型原句、干扰项、译例或可靠来源且归纳已明确时，才补短引用。
- 单题增量不新建或改写 `reviews/`，但应记录日期、年份/题型/题号、证据状态、核心内容和适用边界。
- 单题增量优先写入命中的模块文件并将 `confirmed_increment_count` 加一；原有根目录汇总文件只作兼容索引或去重参考。单题不得把模块升级为 `organized`。

## 内容映射

- 稳定的词汇、搭配、句法、指代、逻辑和原文证据 → 模块 `evidence_and_language.md`。
- 稳定的定位、同义替换、排除、翻译或写作规则 → 模块 `answer_methods.md`。
- 跨模块真正通用的规则才进入根目录 `stable_rules.md`；模块文件保留规范主条目，根目录只作兼容索引或短引用，不完整复制。
- 用户真实错误、犹豫、错误理由、反复追问或自述 → 模块 `user_weaknesses.md`。
- 已接受的完整复盘正文 → `reviews/`，保留答案表、证据、逐项分析、冲突和缺口。

完整题面不要重复复制到汇总文件；用年份、题型、题号和 review 相对路径建立短引用。

## 相近内容五态归并门

单题增量和完整复盘派生规则都必须先检索命中模块及必要的相邻模块。比较语言现象、句法/搭配/逻辑结构、题型信号、定位方式、同义替换、干扰项机制、翻译处理或写作功能、适用边界和错因；不能仅因同一单词、表面主题或题号相近就归并。

1. **等价**：可迁移规则和边界实质相同，不新建条目；若本题提供更典型原句、干扰项、译例或可靠来源，只给原条目补年份/题号/review 短引用和 `引用补充时间`。引用补充不算新知识，不登记活动日志。
2. **补充**：同一语言/答题规则，但增加新句法环境、限制条件、排除边界、反例、译法或写作功能，直接扩充原条目；保留原记录时间，新部分写 `补充记录时间`、原文证据和题号。
3. **相邻**：属于同一规则簇/题型技巧池但不能合并成同一规则，在已有父标题下建立子条目，并与相关项短链接；不建立孤立的年份题号标题。
4. **冲突**：原文边界、指代、逻辑、选项判断、译意或规则有效性不一致，在最相关条目下并列旧/新判断、原文证据、年份题号、日期和待核验/采用状态，不覆盖旧复盘。
5. **全新**：完成命中及相邻模块检索后确无合适规则簇，才新建可迁移的顶层条目。

`无需新增` 用于只针对当前语境、机械替换、无迁移价值或原文证据不足的内容。一个问题产生语言证据、答题方法和真实个人弱点时分别判定；个人弱点只进 `user_weaknesses.md`，重复错因应扩充原弱点记录并保留每次用户证据。跨题型存在规范主规则时只保留一个主条目，其他模块用短引用，不全文复制。

预判和拟归并目标必须先向用户展示。双重确认后的复核若改变归并类别、目标或拟写入内容，必须展示修订后的完整归纳并重新确认。

## 完整复盘保存顺序

1. 确认用户同时认可当前“阶段一完整第一版”及末尾归纳的准确性，并明确同意归档；答案表、单段点评、局部批次草稿、单独的“准确”或单独的“保存”均不能替代完整第一版和双重确认。
2. 生成唯一 review 文件名；同分钟重名时追加 `-02`、`-03`，不覆盖历史文件。
3. 以已接受正文为阶段二唯一内容母本。完整读取并执行 [review-artifact-protocol.md](review-artifact-protocol.md)：恢复单段或全部已验收传输段，先取得逐段规范化正文哈希，再按段序拼成一个 review Markdown，并生成相邻 `.review-manifest.json`。只去掉正文边界外的聊天寒暄；BEGIN/END 之间的正文不得删改，“拟沉淀内容”即使不参与派生归并也保留在 accepted review 中。写后验证逐段及 assembled 哈希；原文不可取得时停止并报告归档正文缺口，禁止摘要重建。
4. 对每个派生逻辑项执行上述五态归并后更新命中模块的 `evidence_and_language.md` 或 `answer_methods.md`；仅依据真实用户证据更新 `user_weaknesses.md`。只有跨模块通用规则才同步更新根目录 `stable_rules.md`，且不得重复正文。
5. 更新 `catalog.json`，验证 catalog 与 review manifest 均可解析、review/manifest 路径存在且 `review_id` 与路径唯一。
6. 重新读取新增段落并报告写入路径、来源状态、每项实际归并状态、主条目、增加的题号引用/补充段落和仍待核实的内容。

成组、题型范围或整套复盘不得绕过完整第一版直接从原卷、解析册、旧知识库或记忆重建并保存；若当前对话缺少已接受正文，先索要正文或文件。单题增量只能来自当前已完整回答、已展示具体归纳且获得双重确认的内容，不得用它规避应当完整覆盖的复盘范围。

## 禁止事项

- 未确认时写入。
- 把解析册内容冒充真题原文或正式来源。
- 把通用易错点写成个人薄弱点。
- 用新结论覆盖旧复盘；冲突应并存并标记日期与来源状态。

## 时间字段与活动日志

- 每个实际新增逻辑条目写 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`，元数据写 ISO `recorded_at`，固定 `time_zone: Asia/Shanghai`（中国标准时间）。
- 每份完整 review/addendum 追加且只追加一条 accepted-review 容器记录，以 `derived_record_ids` 关联真实派生记录；每个派生 Markdown 条目自身写完整时间。
- 写入与复读验证成功后，向 `E:\桌面\学习\考研\学习知识库\activity_log.jsonl` 追加一行，保留题型模块、真题年份/题号或语句、原文证据状态、语言/定位/排除/翻译/写作规则摘要及源文件。
- accepted review 与派生稳定规则应通过 review ID 或题号语义去重，周期汇总不得重复计算同一知识点。
- 未双重确认、未成功落盘、已有等价内容和候选薄弱点不登记。真题年份和归档时间分列。
- 等价条目仅补题号/review 引用时，不增加 `confirmed_increment_count`，不登记活动日志；补充、相邻、冲突或全新形成实际逻辑增量时才按增量计数。
