# 英语二真题复盘

围绕真题文章、题目选项、答案/解析和用户作答建立证据链：先核对题面并独立解题，再诊断错误，最后提炼有边界的迁移规则。

把本地英语二知识库作为课程问答的第一检索层。知识库优先是指在判断答案前主动利用相关语言证据、答题方法、稳定规则、真实薄弱点和既有复盘，不是把任意文章或句子强行识别成历年真题，也不是锁定为旧解析的解法。

## 两阶段产出合同

本合同适用于成组、题型范围或整套真题复盘。单题、单句和作文局部问答使用后文的课程内容归纳与确认后增量协议，不要求先生成整套复盘，但不得借单题模式拆散本应完整覆盖的范围。

1. **阶段一：完整复盘成品。**成组、题型范围或整套任务先按 [references/english2_review_prompt.md](references/english2_review_prompt.md) 的完整第一版结构在对话中输出；答案表、简短点评或“拟沉淀内容”都不能替代完整复盘。
2. **阶段二：基于已接受成品整理。**仅在用户明确接受阶段一并确认保存后进行；先归档已接受正文，再从正文提炼稳定规则和真实个人薄弱点。
3. 不得绕过阶段一直接从 PDF、解析册或零散笔记写知识库；阶段二不得暗改、缩写或重建阶段一正文。
4. 整套真题分批时，每批先完成对应题型的完整第一版；全部批次结束后再做整卷覆盖表、修正记录和缺口审计，然后等待保存确认。

长篇 Stage A 允许在同一 Codex 任务中按“传输分段”连续输出。传输分段不是安全题量分批，也不是多个 review：必须使用同一 `dossier_id`、明确正文边界和连续段序，只能在最后一段完成段清单与总覆盖审计后请求验收。完整执行 [references/review-artifact-protocol.md](references/review-artifact-protocol.md)。

### Stage B 正文完整性门

写入前必须从当前任务或明确的已接受文件取得用户实际确认过的 Stage A 完整正文。若正文分段交付，必须先恢复被验收的各段 revision，按连续段序拼成一个 review，并生成相邻 `.review-manifest.json`。归档不得压缩、改写、重排栏目或重新措辞逐题登记；只允许在正文外增加归档元数据和 Stage B 执行记录，并逐段及整体验证规范化正文哈希。若完整正文不可取得，停止并报告归档缺口，不得把短摘要冒充 accepted review。

## 先统一题型池，再逐题复盘

整篇、整套、年度范围或多来源英语二复盘，必须先登记范围内全部显式题目或任务，再建立统一分类池并输出分类结论，之后才按原试卷顺序逐题、逐句或逐任务完整解析。不得只给通用“题型识别表”，也不得让任何显式题目游离在分类池之外。

每道题只有一个主题型，并可附“证据路线、同义替换、干扰机制、语言障碍、篇章功能”等次级标签。类型结论至少包括：识别信号、定位对象、原文证据链、排除/组织方法、典型干扰、适用边界、难度变化和全部关联题号。最终审计题目登记数、主题型归类数和详解数一致。

英语二通常没有固定教材例题。若本轮确有老师讲义、示范文章或例题，每个实际用于总结的案例都在内部关联到统一分类池的一个主题型，只贡献语言与方法结论；不显示逐例题号、题面、完整解析或案例覆盖率，也不计入真题/显式练习分母。用户明确点名时才展开。真题原文、选项和用户指定练习始终属于显式范围，必须完整解析。

## 预建题型模块

英语二不虚构教材章号，按词汇、语法与长难句、完形、阅读 Part A、新题型、翻译、小作文和大作文建立八个等价模块。先用 `catalog.json` 的别名、关键词、年份和题型路由；`organization_status: skeleton` 只代表空模块可接收问题，不能表述为该题型已经整理。

对尚未整理的模块，依据当前真题原文、用户句子和实际解析作答；缺原文时明确证据缺口，不把常识或记忆补成真题。课程内容回答仍执行具体归纳和双重确认，确认后写入对应模块并增加 `confirmed_increment_count`，但不因单题升级完成状态。跨题型整卷 review 只能形成 `accepted_review_refs` 和 `partially-organized`，不等于各题型已完整整理；只有独立满足完整第一版和覆盖要求的范围才能标记 `organized`。

## 先判定是否属于课程内容

- **触发归纳与归档提醒：**真题原文理解、词汇/搭配/句法、题干与选项证据、定位和同义替换、排除逻辑、翻译处理、写作表达、错因标签和迁移规则。
- **不触发：**是否已整理或保存、文件路径和结构、题数/覆盖率、更新时间、任务进度、资料是否存在、skill 触发与保存规则、知识库管理。这些问题直接回答，结尾不出现“待确认”或归档邀请。
- **混合问题：**只归纳能独立用于后续复习的英语内容；文件、进度、来源状态和规则说明不得写成英语知识或个人弱点。

## 工作流

1. 提取年份、题型、文章/段落、题干、全部选项、用户答案与理由、标准答案和解析。图片模糊或字段缺失时列出缺口，不猜原文。
2. 通过 `catalog.json` 的题型、年份、关键词和语言特征路由模块，并在作答前检索相关 `evidence_and_language.md`、`answer_methods.md`、`stable_rules.md` 和 `user_weaknesses.md`；不能因为模型本身能读懂原文就跳过检索。
3. 若题面、年份题号或关键句表明它与已接受复盘中的真题或案例高度相似，主动检索 `reviews/` 并读取匹配段落；没有实质匹配时不得硬套年份、原文或旧解析。
   - 相似检索还要比较语言现象、句法/搭配/逻辑结构、题型信号、定位方式、干扰项机制、翻译处理或写作功能；不能只按同一单词、题号或表面主题归类。
4. 检索后、正式解答前必须判定并按需显示“已整理命中提醒”；该提醒只说明来源状态，不是归档邀请或写入授权。
   - `EXACT_ACCEPTED`：年份、题型/文章、题号或句段位置、题目原文/关键句和选项结构均对应同一条已接受复盘。先读取精确段落，再提示：`已命中既有整理：{年份/题型/题号或句段}。本次先以该复盘为底稿，再回答你当前问法。`
   - `RELATED_ACCEPTED`：不是同一道原题，但语言现象、定位方式、同义替换、干扰项机制、翻译处理或写作功能可迁移。读取相近条目后提示：`已命中相关整理：{语言点/方法/题型}；不是同一道原题。`
   - `DRAFT_OR_SKELETON`：只有题型骨架、待验收草稿、未接受复盘或未经核实的旧产物。不得说“已整理”；必要时只说明“已有路由骨架/待验收草稿，但没有可复用的已接受整理”。
   - `NO_HIT`：没有实质匹配时不显示命中提醒，依据当前原文独立作答。
   - `CONFLICT`：既有接受复盘与当前原文版本、选项、句法边界或解析结论冲突时，先说明冲突，再重核原文和来源。
   - 同题号但年份、题型或原文不同不得判为精确命中。提醒不得暴露绝对路径、提前倾倒旧答案、暗示用户薄弱或声称本轮已保存。
5. 利用检索内容辅助定位，再独立给出答案、原文证据和置信度，并比较用户与解析。等价的不同定位或表述可以保留；若选项、句法边界、指代、逻辑关系或译意不一致，必须回查匹配归档并重核原文。
6. 整套或成组复盘先列范围；单次默认不超过一篇阅读或 25 道小题，超出时先按连续范围拆分。只有既有 accepted 整卷的纯分类追补可以例外一次处理全卷：每个显式项目必须有可直接定位、可复读的 accepted 详解，本轮只能登记、分类、审计和短链，不得重写逐题分析。任一项目缺少可定位详解时，必须回到安全连续批次恢复并重新验收。
7. 完整读取 [references/english2_review_prompt.md](references/english2_review_prompt.md)，按其“完整第一版输出结构”和对应题型执行。若需要传输分段或归档完整复盘，同时完整读取 [references/review-artifact-protocol.md](references/review-artifact-protocol.md)。用户要求“先提示/不公布答案”时采用分级提示。
8. 错因使用 V/S/L/P/I/R/M/A/O/T/C/G/F/K/E/TR/CO 标签。用户主动给出正确译法、选项结论或语言规则，不自动证明“已掌握/不薄弱”，也不自动构成薄弱点；结合语气、理由和上下文判断，证据不足时标为 `候选薄弱点（待确认）` 并向用户确认。
9. 每题给出“下次遇到同类结构先检查什么”及适用边界；不把老师技巧写成绝对规律。
10. 单题或单点课程问答必须以“本次英语问题归纳（待确认，尚未保存）”收尾，包含题目/语句、原文证据、核心结论、定位或语言规则、选项/表达判断、迁移边界、错因标签、掌握度判断、建议归档、拟写入内容、`归并判定（预判）`和`拟归并目标`；使用 `等价 / 补充 / 相邻 / 冲突 / 全新 / 无需新增`。精确命中且没有可复用新增通常判为 `等价` 或 `无需新增`；新增讲法或边界判为 `补充`；核实后的不一致判为 `冲突`。
11. 成组或整套阶段一复盘必须以“本次英语复盘归纳（待确认，尚未保存）”收尾，概括范围、覆盖、关键规则、真实错因、冲突/缺口和拟沉淀内容，并对每个派生逻辑条目给出归并预判与目标；该归纳不能替代完整第一版。分段时仅最后一段出现该验收收尾，并附完整段清单。
12. 两种模式都要询问归纳是否准确及是否同意归档。只有用户同时认可当前归纳准确并明确同意归档后，才完整读取 [references/storage-protocol.md](references/storage-protocol.md)，复核目标并执行五态归并；若类别或目标发生实质变化，必须展示修订归纳并重新等待双重确认。完整 review/addendum 还必须通过 [references/review-artifact-protocol.md](references/review-artifact-protocol.md) 的前端发布门；缺成对 manifest、校验失败或替代关系未登记时不得报告已归档/已完成。

## 题型重点

- 阅读：原文定位、关键句、同义替换、正确项依据、A—D 逐项排除、用户错因。
- 完形：词性/搭配、句内语义、前后句逻辑、篇章复现、四项比较。
- 新题型：锚点、同义对应和段落逻辑；不默认全文翻译。
- 翻译：主干、修饰与逻辑、直译、中文重组、逐处比较。
- 作文：先评价用户真实作文，再给最小修改版、提升版和重写任务。

## 证据与保存边界

- 证据优先级：题目原文/真题 > 正式答案与解析 > 权威解析 > 多来源经验 > 老师方法 > AI 推断。
- 不用“语感”作为唯一依据，不把常识补成原文结论。
- 官方答案、解析、AI 推导和用户判断分开标识；AI 答错时说明最初误读与修正规则。
- 未明确确认时不写文件；若确认保存但当前对话没有已接受正文，请索要正文或文件，不凭记忆重建。
- 对单题增量，双重确认后只更新稳定规则或真实个人弱点，不新建整卷 review；对成组/整卷复盘，仍严格执行完整第一版的两阶段合同。
- 课程内容问答必须使用具体归纳，不能只问“要不要保存”；管理和状态问题不得追加归档提醒。
- 判断用户掌握度时，独立给出原文证据、语言理由和迁移边界可视为本轮掌握信号；“是不是/我感觉/可能”、猜选、反复确认、自我纠正、前后矛盾、提示后才答对或说不清依据，只能形成候选薄弱点。
- 若不明确，询问“这是你已经掌握后的总结，还是你仍容易混淆、希望记录为薄弱点？”候选状态不得写入；用户回答后必须修订完整归纳并重新取得准确性与归档双重确认。不得保存“用户不薄弱/已掌握”的负面画像。

## 记录时间与活动日志

每个成功归档的逻辑条目必须带实际归档时间：Markdown 写 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`，元数据写 ISO `recorded_at`，统一使用 Asia/Shanghai（中国标准时间，东八区）。再向 `E:\桌面\学习\考研\学习知识库\activity_log.jsonl` 追加记录，保留题型模块、真题年份/题号、原文证据状态、规则或错因摘要及源文件。

每份完整 review 或 accepted addendum 必须有且仅有一条 accepted-review 容器记录，并以 `derived_record_ids` 关联真实派生增量。每个派生 Markdown 逻辑条目自身都必须包含完整时间，不得只把日期写在标题里。

只有双重确认且写入成功后才登记；去重未新增、候选薄弱点和只讨论未归档的内容不登记。真题年份、解析发布日期、核验日期和知识库记录时间不得互相替代。
