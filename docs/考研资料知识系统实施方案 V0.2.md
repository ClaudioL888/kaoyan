# 考研资料知识系统实施方案 V0.2

版本日期：2026-08-16  
定位：批量处理几千页之前的工程收口方案。原始 V0.1 需求文档保持不变，本文件记录当前实现与修订路线。

当前修订：撤回批量链路中的 AI 校验/API 接入计划。AI 视觉能力不作为本阶段实现项、验收项或批量放行依赖；待结构底座、人工 Gold Dataset 和传统/本地 Parser 评估完成后，再单独立项评估。

## 1. 当前结论

项目已经完成“可追溯页面与结构化对象底座”的主要原型，但尚未达到批量 OCR 放行条件。

已证明：

- 原 PDF 作为不可变 SourceVersion 保存；
- 页面使用固定 DPI 的规范分析图，并保存到 PDF 页面坐标的 affine transform；
- Source、SourceVersion、Document、Page、Rendition、Asset 可以持久化；
- 单页失败不会阻止后续页面处理；
- 外部 Parser 结果可以转换成内部 Observation；
- 六类真实资料各 5 页，共 30 页 POC 的文件哈希、引用关系、坐标变换和视觉渲染通过。

尚未证明：

- 中文 OCR、公式 LaTeX、图形结构识别的语义准确率；
- 题号、跨页题、官方答案匹配的准确率；
- Parser 重跑后稳定实体能正确继承人工修订；
- 传统/本地 Parser 在真实标注集上的准确率、性能和稳定性。

因此当前状态是：**结构底座可继续迭代，暂不允许全量处理几千页。**

## 2. 三项冻结设计

### 2.1 Canonical Schema

数据分三层：

```text
原始层：Source / SourceVersion / PDF / 原始页图
观测层：ParseRun / BlockObservation / FormulaObservation / FigureObservation
稳定层：Block / TextRevision / FormulaOccurrence / FigureOccurrence / Question / Solution
```

Parser 输出只能进入观测层；OCR、版面分析工具和人工识别结果允许并存；稳定实体通过 reconciliation 关联 Observation；人工修订创建新 revision，不覆盖机器原始结果。

所有 canonical 模型必须拒绝未知字段并验证赋值后的状态。

### 2.2 ID Strategy

- `source_id`：人工登记、可读、不可从文件名自动重算；
- `source_version_id`：`source_id + PDF SHA-256`；
- `page_id`：SourceVersion + PDF 物理页序号；
- Observation ID：包含 `parse_run_id`，只在单次解析运行内稳定；
- Block、Formula、Figure、Question、Solution：确定性 UUID5 形式的长期实体 ID。

仍需补强：当前 entity helper 以候选身份键生成，bbox 改变仍可能生成新 ID；批量前必须增加 Entity Registry 和 Observation Reconciliation。Question ID 应使用逻辑 source + 书内题目键 + 消歧键，不得依赖 OCR 文本或题型分类。

### 2.3 原图/文字/公式引用

```text
SourceVersion
  → Original PDF Asset
  → Page
  → PageRendition（规范分析图）
  → SourceAnchor（page_id + rendition_id + bbox）
  → Observation
  → Stable Entity / Revision
```

`bbox` 使用规范 PageRendition 的左上角像素坐标。PageRendition 必须保存到 PDF points 的 affine transform。原始内嵌页图只作为辅助资产，不能直接假设其像素等于 PDF 页面坐标。公式、图片、表格裁切必须由父资产和 CropSpec 确定性生成。

## 3. AI 校验回撤决定

本阶段不接入 Codex Vision/OpenAI API，也不把 AI 生成或 AI 复验纳入生产处理链路。以下组件从“批量前必须实现”调整为延期评估项：

- `CodexVisionAdapter`；
- `CodexVerifier`；
- Observation Comparator 的 AI 双路比对模式；
- OpenAI API 批处理、凭据、成本与限流设施；
- AI 自动接受阈值和 AI Review Queue。

当前对话中的 Codex 仍可用于少量页面的人工辅助观察、方案讨论和结果解释，但这些结果不直接写入 canonical 数据，也不构成独立校验或批量放行依据。

当前生产候选流程恢复为：

```text
PageRendition
  → 传统/本地 Parser（待 POC 选型）
  → Observation
  → 确定性完整性检查
  → 与人工 Gold Dataset 比较
  → 人工抽检/修订
  → Stable Entity / Revision
```

以后若重新引入 AI，仍必须遵守 Observation 分层、完整 provenance 和原图权威性原则，但需要另行修订方案后再实施。

## 4. Gold Dataset 与复验依据

批量前建议建立至少 60～90 页可人工核验的数据集：

- 高数/线代公式和复杂排版 20～30 页；
- 408 题集、树、图、流程图、表格 20～30 页；
- 官方解析、多题连续排版和跨页解答 20～30 页。

每页标注物理页序号、印刷页码、Block bbox/type/reading order、正文标准转录、公式标准 LaTeX、图形/表格区域、题目边界和跨页关系。

复验必须同时依靠：

1. SHA-256、引用完整性、坐标映射、裁切可重建等确定性检查；
2. Gold Dataset 的文字、公式、Layout、Question 指标；
3. 至少一种传统/本地 Parser 与人工标注比较；
4. 随机人工抽检；
5. Parser 升级后的回归测试。

## 7. 批量前剩余里程碑

### Milestone A：结构底座收口

实现指定页 retry/CLI、补齐 pdfplumber 依赖、修正 pipeline 配置、实现 Crop Service、Entity Registry、Observation Reconciliation、Parser Run 日志和可恢复状态。

### Milestone B：人工 Gold Dataset

从高数、线代和 408 资料中完成 60～90 页人工标注，建立文字、公式、版面、题目边界和跨页关系的评价基准。

### Milestone C：传统/本地 Parser POC

至少接入一种可重复运行的传统/本地 Parser（候选如 MinerU 或 PaddleOCR），与 Gold Dataset 比较，确定主 Parser、人工复核规则和回归阈值。

### Milestone D：预批量演练

连续处理 100～200 页，模拟失败、中断、重试、Parser 升级和人工修订继承，统计速度、磁盘、错误率和人工复核比例。

## 8. 批量放行条件

- 原 PDF、规范页图、原始内嵌图、公式/图形裁切零丢失；
- 主要对象全部可回溯到 `source → page → rendition → bbox`；
- Integrity Gate 100% 通过；
- 失败页有状态、原因和指定页重试能力；
- Gold Dataset 指标达到确认阈值；
- Parser 重跑不覆盖人工修订；
- 100～200 页预批量演练完成；
- Schema、ID 和引用规则冻结。

AI API、AI 校验器和 AI 自动接受率不属于当前放行条件。

满足以上条件前，不执行全量几千页处理。
