# 四科复习 Skill 统一修改规则

生效日期：2026-08-19

## 默认修改范围

用户提出修改考研复习、问答、错因诊断、知识归纳或知识库存储规则时：

- 若用户明确指定科目，只修改该科目相关 Skill。
- 若用户未指定科目，默认同时检查并按各科特点修改四科相关 Skill，不得只改当前对话涉及的一个科目。

四科映射：

- 数二：`answer-math-kb`、`review-math-chapter`
- 408：`study-408`
- 英语二：`review-english2-real-tests`
- 政治：`review-politics-exam`

## 四科共同归档门禁

1. 先区分课程内容与管理/状态问题。
2. 课程内容回答末尾必须给出科目专属的具体归纳，并询问归纳是否准确、是否同意归入知识库。
3. 只有用户同时认可归纳准确并明确同意归档，才允许写入；两个确认可以在同一条回复中完成，但不能相互推定。
4. 用户修正归纳后，必须重新展示完整修订版并再次等待双重确认。
5. 是否已保存、文件路径、覆盖数量、更新时间、任务进度、资料状态、Skill 规则和知识库管理等问题直接回答，不出现“待确认”或归档邀请。
6. 混合问题只归纳可独立复习的课程内容，不把文件、进度、规则或配置写入学习知识库。
7. 无新增价值或已有等价内容时明确标注并执行去重，不为满足格式制造条目。
8. 用户主动说出正确结论，只能证明本轮表述正确，不能自动判为“已掌握/不薄弱”，也不能自动判为薄弱点。Agent 必须结合语气、理由、上下文和迁移能力判断。
9. 猜测、犹豫、自我纠正、反复确认、前后矛盾、依赖提示或说不清理由时，只能标记为 `候选薄弱点（待确认）`；证据不够时向用户确认这是已掌握后的总结，还是仍易混淆且希望记录的薄弱点。
10. 候选薄弱点不得落盘；用户澄清后必须修订完整归纳，并重新取得准确性认可与归档授权。不得保存“用户不薄弱/已经掌握”的负面画像。

## 科目差异

- 数二：重点归纳数学结论、识别信号、标准方法、成立条件、易错边界和真实错误证据。
- 408：按数据结构、计组、操作系统、计网分别保留算法状态、复杂度、位宽字段、信号量时间线、地址与逐跳过程。
- 英语二：保留真题原文证据、定位与同义替换、语言规则、选项逻辑、翻译/写作迁移和错因标签。
- 政治：保留资料性质与日期、知识卡、概念边界、材料映射、答题方法和错误层级；时政与预测内容必须保留版本边界。

章节、成组或整卷复盘继续执行各科原有的完整第一版合同；末尾归纳和双重确认不能替代完整成品。

## Stage A 分段、拼接与前端复用

1. 四科章节、成组或整卷 Stage A 优先一次回复完成；受单次输出长度限制时，允许在同一 Codex 任务内连续分段。
2. 传输分段不是题量安全分批，也不是多个 accepted reviews。各段必须使用同一 `dossier_id`、连续段序、明确正文边界；中间段的“继续”不构成准确性确认或归档授权。
3. 只有最后一段可以给出总段清单、完整覆盖审计、待确认归纳和归档询问。用户双重确认的对象是各段按原序拼接后的完整 Stage A。
4. 阶段二必须先恢复所有被验收段，按 UTF-8/LF 规范化后逐段计算 SHA-256，再拼成一个 review Markdown；不得压缩、改写、重排或用摘要/PDF重扫填补缺段。
5. 每份完整 review 同目录保存一个同名 `.review-manifest.json`，记录 review/dossier/科目/单元/模板、来源 thread/turn/item、段序/revision/范围/字符数/哈希、assembled 哈希、接受时间和双重确认状态。
6. 缺段、截断、重复、段序不明或无法证明属于已验收版本时停止归档并报告正文缺口，不得标记为完整 accepted Stage A。
7. 本地只登记一个 accepted-review 容器；传输段不分别计数，派生逻辑项继续用 `derived_record_ids` 去重。
8. 后续前端以 manifest 作为真实性与分段来源入口，以 review Markdown 作为正文入口；模板视图只能做虚拟映射，原序正文必须保持 assembled Stage A 段序。

四科具体协议分别位于各 Skill 的 `references/review-artifact-protocol.md`；确定性拼接工具为 `tools/assemble_stage_a_review.py`。

## 四科预建章节骨架

1. 四科知识库应预先建立章节或等价题型模块的空骨架，并在目录中登记别名、关键词、路径、来源依据和整理状态。
2. 数二按数学二实际范围的高数、线代讲次建章；408 按数据结构、计组、操作系统、计网教材章建章；英语二按基础能力与真题题型建等价模块；政治按考试学科模块建框架，时政保持动态版本边界。
3. 空骨架统一标记 `organization_status: skeleton`，只代表“能够路由”，不得称为“已整理”“已完成”或“已有知识”。已有完整复盘的单元标记 `organized`；仅链接跨模块完整复盘的单元可标记 `partially-organized`。
4. 用户询问尚未整理章节时，Agent 先命中对应骨架，再读取用户给出的题目、相关教材/真题/解析或进行清楚标识的独立推导后回答；不得因骨架为空而拒答，也不得假装知识库已有结论。
5. 回答结尾仍执行科目专属归纳与双重确认。只有确认后才能将增量写入对应骨架；单题增量只增加 `confirmed_increment_count`，章节仍保持 `skeleton`，不能因此升级为完整整理。
6. 只有经过该科目的完整第一版合同、覆盖核对并完成归档，才能把章节升级为 `organized`。跨模块整卷复盘只形成链接时，不自动宣布各模块完整。
7. 若新版本资料出现目录中没有的真实章节，先核对来源再补建“仅元数据+空文件”的骨架；未经双重确认不得顺带写入课程结论。

当前骨架总清单见 `framework_manifest.json`，构建脚本见 `tools/build_subject_skeletons.py`。

## 记录时间与周期汇总

1. 每次实际写入的逻辑记录必须带 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`，元数据使用 `recorded_at` ISO 8601，并统一标记 `time_zone: Asia/Shanghai`（中国标准时间，东八区）。
2. 真题年份、资料发布日期、来源核验日期、用户作答日期和知识库记录时间不得混为一个字段。
3. 成功写入后必须向根目录 `activity_log.jsonl` 追加一行；每行对应一个可独立理解的逻辑记录，至少包含科目、章节/模块、类型、标题、摘要、源文件、题号/范围、来源状态和时间。
4. 未获双重确认、候选薄弱点、仅在对话中讨论而未归档的内容不得进入活动日志。
5. 日/周/双周汇总只读取活动日志和其指向的知识文件，按完整自然日的前1天、前7天、前14天统计；不得用文件修改时间猜测新增记录。
6. 周期汇总按数二、408、英语二、政治分类，408 再分四个子科目；有关联题目时提供题号/范围、题面摘要、关键步骤、易错边界和迁移例子。过长时写入 `periodic-reports/` 并在对话中给出摘要和路径。
7. 周期汇总是只读管理任务，不新增课程知识、不改变掌握度，也不触发“是否归入知识库”的提醒。

详细字段和窗口定义见 `记录时间与周期汇总规范.md`。
