## 3. 本范围知识体系总览

1. 栈：具有 LIFO 特性；顺序栈和链栈只是同一 ADT 的不同实现。所有公式都要先固定 `top` 指向栈顶元素还是下一空位、增长方向及下标范围。
2. 队列：具有 FIFO 特性；普通顺序队列会出现假溢出，循环队列通过取模复用空间。`front/rear` 的语义、是否牺牲一个单元、是否增加 `size/tag` 决定空满条件。
3. 栈和队列的应用：栈用于括号匹配、表达式处理和递归；队列用于层序遍历、BFS、缓冲和公平调度；双端队列题以允许操作的端点为约束。
4. 数组和矩阵：连续存储时先判行/列优先、上下界和元素宽度；特殊矩阵按规律映射，稀疏矩阵以三元组表或十字链表存储非零元，但失去随机存取特性。

## 4. 核心知识、重点与难点系统讲解

- 指针语义优先于公式：`top=-1` 常表示栈顶元素下标；`top=0` 也可能表示下一空位。循环队列的 `rear` 可能指队尾元素，也可能指下一空位。
- 出栈序列判断：按照“需要哪个元素就压到哪个元素；若当前栈顶仍不是目标元素，则序列非法”进行模拟。等价不变量是：栈中未出元素的可弹出相对次序已经固定。
- 循环队列：
  - 牺牲一格法：空为 `front==rear`，满为 `(rear+1)%M==front`；
  - `size` 法：用元素数区分空满；
  - `tag` 法：用最近一次造成指针相等的操作区分空满。
- 表达式与递归：中缀转后缀时操作数直接输出，运算符按优先级出入栈；递归调用树的结点数才是调用次数，系统栈保存活动记录。
- 矩阵映射：统一计算“目标元素之前已经存入多少元素”，最后再根据数组下标从 0 还是 1 开始进行平移。

## 6. 重点难点易错点专项

- 把逻辑结构与存储结构混为一谈：栈、队列都是线性逻辑结构，差异在操作限制。
- 只记 `front==rear` 而不说明它表示空还是满：必须同时给出消歧方案。
- 仅凭直觉判断出栈序列：应记录栈内容或前缀深度。
- 两栈模拟队列时，在 S2 非空的情况下把 S1 倒入 S2，会破坏旧元素的优先级。
- 括号匹配遇右括号前不判空，会发生非法 Pop。
- 矩阵压缩忘记行/列优先、矩阵下标、数组下标或常量存储位。

### 3.1选01｜答案 B｜T01

题目：栈和队列具有相同的（ ）。

A. 抽象数据类型　B. 逻辑结构　C. 存储结构　D. 运算

- A×：栈和队列是不同的 ADT，操作接口及约束不同。

### 3.1选02｜答案 C｜T01

A. 顺序存储的线性结构

C. 限制存取点的线性结构  
D. 限制存取点的非线性结构

### 3.1选03｜答案 B｜T01

题目：下列选项中，（ ）不是栈的基本操作。

A. 删除栈顶元素　B. 删除栈底元素　C. 判断栈是否为空　D. 将栈置为空栈

- A✓基本操作：即 Pop。
- B×且为本题答案：栈不允许直接从栈底删除；只能组合基本操作间接完成。

### 3.1选04｜答案 C｜T01

题目：用数组 `a[n]` 存储栈，初始栈顶指针 `top=-1`，元素 `x` 入栈的操作是（ ）。

A. `a[--top]=x`　B. `a[top--]=x`　C. `a[++top]=x`　D. `a[top++]=x`

- A×、B×：先减或后减会向负下标移动。
- C✓：`top=-1` 表示空栈且 `top` 指向栈顶元素；首元素应写入 `a[0]`。
- D×：会先写 `a[-1]`，发生越界。
- 不变量：有效栈区为 `a[0..top]`。

### 3.1选05｜答案 B｜T01

题目：用数组 `data[1..n]` 存储栈，初始栈顶指针 `top=1`，元素 `x` 入栈的操作是（ ）。

A. `data[top--]=x`　B. `data[top++]=x`　C. `data[--top]=x`　D. `data[++top]=x`

- A×：写入后向低地址移动，与题设表示不符。
- B✓：此时 `top` 表示下一空位，首元素写 `data[1]` 后再自增。
- C×：会减到下标 0。
- D×：会跳过 `data[1]`。
- 易错点：相同变量名 `top` 可以有不同语义，不能机械套第04题。

### 3.1选06｜答案 A｜T01

题目：用数组 `data[1..n]` 存储栈，初始 `top=n+1`，元素 `x` 入栈的操作是（ ）。

A. `data[--top]=x`　B. `data[top++]=x`　C. `data[top--]=x`　D. `data[++top]=x`

- A✓：栈从高地址向低地址增长，首元素应写入 `data[n]`。
- B×、C×：都会先访问越界位置 `data[n+1]`。
- D×：继续向更高地址移动。

### 3.1选07｜答案 A｜T01

题目：空栈的栈顶指针为 `1000H`，栈向高地址增长，每个元素占一个存储单元。执行 Push、Push、Pop、Push、Pop、Push、Pop、Push 后，栈顶指针为（ ）。

### 3.1选08｜答案 A｜T01

题目：和顺序栈相比，链栈较明显的优势是（ ）。

A. 通常不会出现栈满　B. 通常不会出现栈空

- A✓：链栈动态申请结点，通常不受固定数组容量约束。
- B×：链栈也可能为空。
- C×、D×：两种实现的栈顶插入、删除都可为 O(1)，不是决定性优势。

### 3.1选09｜答案 C｜T01

题目：链表不带头结点且所有操作均在表头进行，下列最不适合作为链栈的是（ ）。

A. 只有表头指针的双向循环链表  
B. 只有表尾指针的双向循环链表  
C. 只有表头指针的单向循环链表  
D. 只有表尾指针的单向循环链表

- A×：双向循环结构可由表头快速定位表尾并维护循环。
- B×：尾指针可通过双向链接 O(1) 找到表头。
- C✓：只有头指针的单向循环链表在修改表头后，为恢复尾结点指向新表头，需要 O(n) 找尾。
- D×：尾指针的 `next` 就是表头，可 O(1) 找到操作位置。

### 3.1选10｜答案 C｜T01

题目：向栈顶指针为 `top` 的无头结点链栈中插入结点 `x`，应执行（ ）。

A. `top->next=x`  
B. `x->next=top->next; top->next=x`  
C. `x->next=top; top=x`  
D. `x->next=top; top=top->next`

- A×：未让 `x` 成为新栈顶，还可能丢失结构语义。
- B×：这是在原栈顶之后插入。
- C✓：先让 `x` 指向旧栈顶，再更新 `top`。
- D×：第二句使 `top` 又指回旧栈顶。
- 不变量：操作后从新 `top` 可达全部原结点，且没有断链。

### 3.1选11｜答案 D｜T01

题目：无头结点链栈执行 Pop，并把出栈元素存入 `x`，应执行（ ）。

A. `x=top; top=top->next`  
B. `x=top->data`  
C. `top=top->next; x=top->data`  
D. `x=top->data; top=top->next`

- A×：把结点地址而不是数据值赋给 `x`。
- B×：只读值，没有删除栈顶。
- C×：先移动后读取，取得的是新栈顶值。
- D✓：先保存旧栈顶数据，再移动指针。
- 实现边界：实际代码还应暂存旧结点并释放，且 Pop 前判空。

### 3.1选12｜答案 A｜T01

题目：执行：

`InitStack(st); Push(st,a); Push(st,b); Pop(st,x); GetTop(st,x);`

变量 `x` 的值为（ ）。

A. `a`　B. `b`　C. `NULL`　D. `false`

- A✓；B×是中间状态；C×、D×不是最终读取结果。

### 3.1选13｜答案 B｜T02

题目：3 个不同元素依次入栈，能得到（ ）种不同的出栈序列。

A. 4　B. 5　C. 6　D. 7

- B✓：数量为第三个 Catalan 数  
  \[
  C_3=\frac{1}{4}\binom{6}{3}=5.
  \]
- 合法序列可枚举为 `abc、acb、bac、bca、cba`。
- A×、C×、D×：不等于合法序列总数。
- 边界：不是任意排列都能作为栈输出，`cab` 即不可实现。

### 3.1选14｜答案 D｜T02

题目：`a,b,c,d,e,f` 依次入栈，允许入栈、出栈交替进行，不会出现的出栈序列是（ ）。

A. `fedcba`　B. `bcafed`　C. `dcefba`　D. `cabdef`

- A×：全部入栈后逆序弹出即可。
- B×、C×：都能构造相应 Push/Pop 过程。
- D✓：`c` 首先出栈时，`a、b` 已留在栈中且 `b` 位于 `a` 上方，不可能随后按 `a、b` 输出。
- 核心不变量：尚未出栈的较早输入元素，其可弹出次序受栈内逆序约束。

### 3.1选15｜答案 A｜T02

题目：4 个元素按 `a,b,c,d` 依次入栈，以 `cd` 开头的出栈序列有（ ）个。

A. 1　B. 2　C. 3　D. 4

- 再输出 `d`：压入并弹出 `d`。
- 此时栈中只能按 `b,a` 弹出，因此唯一序列是 `cdba`。

### 3.1选18｜答案 D｜T02

### 3.1应01｜T02

题目：5个元素按 `A,B,C,D,E` 入栈。所有可能的出栈序列中，第一个出栈元素为 C、第二个为 D 的序列有哪些？

#### 状态推导

C 首先出栈：

1. 依次压入 A、B、C；
2. 弹出 C；
3. 压入 D；
4. 弹出 D。

此时栈内自底向顶为 `[A,B]`，E 尚未入栈。剩余过程只有三类：

- E 立即入栈、出栈，再弹 B、A：`C,D,E,B,A`；
- 先弹 B，再入出 E，最后弹 A：`C,D,B,E,A`；
- 先弹 B、A，再入出 E：`C,D,B,A,E`。

#### 结论

全部序列为：

- `CDEBA`
- `CDBEA`
- `CDBAE`

#### 正确性与边界

- 不变量：栈中 A、B 的相对弹出次序只能是 B、A。
- E 是唯一尚未入栈元素，因此只需枚举它插入固定序列 `B,A` 的3个位置。
- 枚举完备且无重复。
- 本题规模固定；一般插入位置枚举为 O(n)。

### 3.1应02｜T02

题目：入栈序列为 `A,B,C,D,E`。能否得到出栈序列 `B,C,A,E,D` 和 `D,B,A,C,E`？说明理由。

#### （1）`B,C,A,E,D`

可以得到：

| 操作 | 栈状态 | 输出 |
|---|---|---|
| Push A | `[A]` | |
| Push B | `[A,B]` | |
| Pop | `[A]` | B |
| Push C | `[A,C]` | B |
| Pop | `[A]` | B,C |
| Pop | `[]` | B,C,A |
| Push D | `[D]` | |
| Push E | `[D,E]` | |
| Pop | `[D]` | B,C,A,E |
| Pop | `[]` | B,C,A,E,D |

所以 `BCAED` 可得。

#### （2）`D,B,A,C,E`

不能得到。若 D 第一个出栈，则 A、B、C 已经按该顺序入栈，D 出栈后栈内自底向顶为 `[A,B,C]`。此时栈顶是 C，不可能越过 C 先弹出 B、A。

#### 通用判定算法

依次扫描目标输出：

1. 若栈顶等于当前目标，弹出；
2. 否则继续从输入序列压栈，直到压入目标或输入耗尽；
3. 若输入耗尽后栈顶仍不是目标，则非法。

循环不变量：已经输出的前缀与目标一致；栈保存已经输入但尚未输出的元素。时间 O(n)，辅助空间 O(n)。

### 3.1应03｜T02｜题面—正式解析冲突

题目：栈的初态、终态均为空，以 I 表示入栈、O 表示出栈。

（1）判断下列序列是否合法：

A. `IOIOIOO`  
B. `IOOIOIO`  
C. `IIIOIOIO`  
D. `IIIOIOO`

（2）设计算法判断任意 I/O 操作序列是否合法。

#### （1）严格按印刷题面逐项判断

令 `depth` 表示当前栈深，I 使其加1，O 使其减1；合法序列必须满足任一前缀 `depth>=0`，并且最终 `depth=0`。

- A `IOIOIOO`：深度依次 `1,0,1,0,1,0,-1`。最后一次 O 下溢，非法。
- B `IOOIOIO`：深度依次 `1,0,-1,…`。第三步已下溢，非法。
- C `IIIOIOIO`：深度依次 `1,2,3,2,3,2,3,2`？  
  重新按字符核对：该印刷串含 `III O I O I O`，共有4个 I、4个 O；深度为 `1,2,3,2,3,2,3,2` 会显示终值2，这说明视觉串还需逐字符复核。对页面放大后，题面确为 `IIIOIOIO`：其中 I 的数量为5、O为3，终态也不为空，因此非法。
- D `IIIOIOO`：I 为4个、O为3个或受字体混淆影响；按页面可见字符计数，终态不为空，非法。

#### 冲突记录

原书正式解析写“选项 A、D 合法，B、C 非法”，并说明 B 会前缀下溢、C 入出栈次数不等。但这一结论与当前横版题面可见字符不自洽：

- A 的印刷串末尾存在额外 O；
- C/D 中大写字母 I 与字体竖线容易发生排版或转录混淆；
- 因此不能把正式解析答案直接覆盖到当前可见题面。

当前采用状态：

- 正式解析结论：A、D 合法；
- 当前题面独立核算：可见字符串与该答案冲突；
- 最终学习结论：保留为“来源冲突，待勘误版或另一清晰原版核验”，不猜补缺失字符。

#### （2）通用判定算法

```text
Judge(A):
    depth = 0
    for ch in A:
        if ch == 'I':
            depth += 1
        else if ch == 'O':
            depth -= 1
            if depth < 0:
                return false
        else:
            return false
    return depth == 0
```

- 循环不变量：`depth` 等于已扫描前缀中入栈次数减出栈次数，即当前栈内元素数。
- 终止条件：扫描到序列末尾。
- 正确性：前缀非负保证没有空栈 Pop；终值0保证最终为空。
- 复杂度：时间 O(n)，额外空间 O(1)。

### 3.1应04｜T15

题目：单链表表头指针为 L，结点含字符型 `data` 和 `next`。设计算法判断全部 n 个字符是否中心对称。

#### 算法

1. 扫描前 \(\lfloor n/2\rfloor\) 个结点，将字符依次压栈。
2. 若 n 为奇数，跳过中心结点。
3. 扫描后半链表：
   - 每访问一个字符，弹出栈顶；
   - 若二者不同，立即返回 false。
4. 链表扫描结束且栈为空，返回 true。

```text
Palindrome(L, n):
    S = empty stack
    p = first data node of L

    repeat floor(n/2) times:
        Push(S, p.data)
        p = p.next

    if n is odd:
        p = p.next

    while p != NULL:
        if StackEmpty(S):
            return false
        x = Pop(S)
        if x != p.data:
            return false
        p = p.next

    return StackEmpty(S)
```

- 循环不变量：已经检查的后半前缀恰与前半部分对应后缀逆序相等。
- 终止：`p==NULL`。
- 时间 O(n)，辅助空间 O(n)，实际最多存 \(\lfloor n/2\rfloor\) 个字符。
- 边界：空表、单结点均为中心对称；必须先固定 L 是否指向头结点。

### 3.1应05｜T03

题目：两个顺序栈 S1、S2 共享数组 `V[0..maxsize-1]`，栈顶相向增长。设计两栈的入栈和出栈算法。

#### 状态定义

- `top1=-1`：S1 空，从左向右增长。
- `top2=maxsize`：S2 空，从右向左增长。
- 满条件：`top2-top1==1`。
- S1 空：`top1==-1`。
- S2 空：`top2==maxsize`。

#### Push

```text
Push(i, x):
    if i not in {1, 2}:
        return false
    if top2 - top1 == 1:
        return false

    if i == 1:
        V[++top1] = x
    else:
        V[--top2] = x
    return true
```

#### Pop

```text
Pop(i, x):
    if i == 1:
        if top1 == -1:
            return false
        x = V[top1--]
        return true

    if i == 2:
        if top2 == maxsize:
            return false
        x = V[top2++]
        return true

    return false
```

#### 正确性与复杂度

- 状态不变量：
  - S1 有效区为 `V[0..top1]`；
  - S2 有效区为 `V[top2..maxsize-1]`；
  - `V[top1+1..top2-1]` 是共同空闲区。
- 每次 Push 只占用共同空闲区一格；每次 Pop 只释放对应栈顶一格。
- 入栈先判满，出栈先判对应栈空。
- 每个操作时间 O(1)，额外空间 O(1)。

- C×、D×：`front` 不满足首元素位于0的约定。

A. 空：`end1==end2`；满：`end1==(end2+1) mod M`

### 3.2应01｜T05 循环队列 `tag` 状态编码

#### 题目

希望循环队列中的全部数组单元都能得到利用。设置标志域 `tag`，以 `tag=0/1` 区分 `front==rear` 时队列是空还是满。编写相应的入队和出队算法。

#### 任务一：入队算法

约定：

- `front` 指向队首元素；
- `rear` 指向下一可写位置；
- 初始化：`front=rear=0, tag=0`；
- 入队成功后置 `tag=1`；
- 出队成功后置 `tag=0`。

因此：

- 队空：`front==rear && tag==0`
- 队满：`front==rear && tag==1`

```text
EnQueue(Q, x):
    if Q.front == Q.rear and Q.tag == 1:
        return false

    Q.data[Q.rear] = x
    Q.rear = (Q.rear + 1) % MaxSize
    Q.tag = 1
    return true
```

#### 任务二：出队算法

```text
DeQueue(Q, x):
    if Q.front == Q.rear and Q.tag == 0:
        return false

    x = Q.data[Q.front]
    Q.front = (Q.front + 1) % MaxSize
    Q.tag = 0
    return true
```

#### 状态与正确性

- 核心不变量：`front` 是下一出队位置，`rear` 是下一入队位置。
- 指针不相等时，可直接由环上距离确定队列非空且非满。
- 指针相等时：
  - 最近一次改变状态的是入队，说明队尾绕回并追上队首，故为满；
  - 最近一次改变状态的是出队，说明最后一个元素被删除，故为空。
- 入队只有可能使队列变满，因此成功后置 `tag=1`。
- 出队只有可能使队列变空，因此成功后置 `tag=0`。
- 每次操作时间 O(1)，额外空间 O(1)。
- 与牺牲一格法不同，本方案可以存放 `MaxSize` 个元素。

#### 实现边界

- 必须先完成满/空判断，再读写数组。
- `tag` 表示最近一次可能造成指针重合的操作，不是当前元素数。
- 若题设改为 `rear` 指向队尾元素，代码和初值必须重新推导。

### 3.2应02｜T16 使用栈逆置队列

#### 题目

Q 是一个队列，S 是一个空栈。设计算法将队列 Q 中的元素逆置。

#### 算法

```text
ReverseQueue(Q, S):
    while not QueueEmpty(Q):
        x = DeQueue(Q)
        Push(S, x)

    while not StackEmpty(S):
        x = Pop(S)
        EnQueue(Q, x)
```

#### 状态过程

若原队列从队头到队尾为：

```text
a1, a2, ..., an
```

第一阶段全部转入栈后：

```text
栈底 a1, a2, ..., an 栈顶
```

第二阶段依次弹栈并入队，Q 变为：

```text
an, an-1, ..., a1
```

#### 循环不变量

第一阶段：

- S 自底向顶保存 Q 已出队前缀，次序与原队列相同；
- Q 保存尚未处理的原后缀。

第二阶段：

- Q 已重新建立的部分恰为原序列的逆序前缀；
- S 保存尚未弹出的元素。

#### 正确性

栈的 LIFO 恰好把队列的 FIFO 次序反转。所有元素各出队、入栈、出栈、入队一次，不重不漏。

#### 复杂度与边界

- 时间：O(n)。
- 辅助空间：O(n)。
- S 必须能容纳 Q 的全部 n 个元素；若栈容量不足，算法不能直接完成。
- 若入队、出队接口返回成功状态，代码必须检查失败结果。

### 3.2应03｜T16 两个栈模拟队列

#### 题目

用两个栈 S1、S2 模拟一个队列。只允许使用：

- `Push(S,x)`
- `Pop(S,x)`
- `StackEmpty(S)`
- `StackOverflow(S)`

实现：

1. `EnQueue`：元素入队；
2. `DeQueue`：元素出队并存入 `x`；
3. `QueueEmpty`：判断队空。

#### 状态设计

- S1：输入栈，新元素只压入 S1。
- S2：输出栈，最早入队的元素位于其栈顶。
- 只有 S2 为空时，才允许把 S1 全部倒入 S2。

关键不变量：

> S2 中自栈顶向栈底是队列当前较早元素的出队次序；S1 中自栈底向栈顶是较晚元素的入队次序。S2 非空时不得把 S1 倒入，否则新元素会压到旧元素上方，破坏 FIFO。

#### 任务一：EnQueue

若采用可动态增长的栈，入队只需：

```text
EnQueue(S1, S2, x):
    Push(S1, x)
    return true
```

若题目中的两个栈容量固定，则需处理 S1 满：

```text
EnQueue(S1, S2, x):
    if not StackOverflow(S1):
        Push(S1, x)
        return true

    if not StackEmpty(S2):
        return false

    while not StackEmpty(S1):
        y = Pop(S1)
        Push(S2, y)

    Push(S1, x)
    return true
```

解释：

- S1 满且 S2 非空时，不能把 S1 压入 S2，否则会覆盖 S2 中更早元素的出队优先级。
- S1 满且 S2 为空时，可把 S1 全部倒入 S2，腾空 S1 后继续入队。
- 每次转移前仍须确认 S2 容量足够；若两栈容量不同，应单独检查。

#### 任务二：DeQueue

```text
DeQueue(S1, S2, x):
    if not StackEmpty(S2):
        x = Pop(S2)
        return true

    if StackEmpty(S1):
        return false

    while not StackEmpty(S1):
        y = Pop(S1)
        Push(S2, y)

    x = Pop(S2)
    return true
```

当 S2 为空时，S1 的栈底元素是最早入队元素。整体转移后，它成为 S2 栈顶，符合 FIFO。

#### 任务三：QueueEmpty

```text
QueueEmpty(S1, S2):
    return StackEmpty(S1) and StackEmpty(S2)
```

只有两个栈都为空，模拟队列才为空。

#### 正确性

把元素按入队时刻从早到晚记为：

```text
a1, a2, ..., ak
```

整体转移前，S1 自底向顶为同一顺序；转移后，S2 自顶向底为同一顺序。因此连续 Pop(S2) 正好依次输出 `a1,a2,…,ak`。

新入队元素留在 S1，必须等 S2 中旧元素全部出队后才会转移，故不会越过旧元素。

#### 复杂度

- EnQueue：通常 O(1)；固定容量、发生整体转移时最坏 O(n)。
- DeQueue：S2 非空时 O(1)；整体转移时最坏 O(n)。
- 摊还分析：每个元素最多进入 S1 一次、从 S1 转到 S2 一次、从 S2 弹出一次，因此一串操作的摊还时间为 O(1)/次。
- 辅助空间：O(n)。

#### 易错边界

- S2 非空时禁止转移 S1。
- 出队前必须同时检查两个栈。
- 不得每次出队都来回倒栈，否则会把整体复杂度劣化为 O(n) 每次。

### 3.2应04｜2019统考真题｜T06 循环链队复用空间

#### 题目

设计一个队列，满足：

1. 初始时为空；
2. 入队时允许增加队列占用空间；
3. 出队后，出队元素所占空间可以重复使用，整个队列占用空间只增不减；
4. 入队、出队时间复杂度始终为 O(1)。

回答：

1. 选链式还是顺序存储？
2. 画出初态，给出队空、队满条件；
3. 给出第一个元素入队后的状态；
4. 给出入队、出队的基本过程。

#### 任务一：存储结构选择

选择循环单链表。

理由：

- 顺序存储通常需要预设容量；扩容时可能整体搬迁，不能保证每次入队始终 O(1)。
- 链式存储可按需增加结点。
- 出队结点不释放，而是保留在循环链表中作为可复用空闲结点。
- 维护 `front、rear` 后，入队和出队都只移动指针或插入一个结点，始终为 O(1)。

结构可理解为“两段式循环链表”：

- 从 `front` 到 `rear` 之前为有效队列区；
- 从 `rear` 到 `front` 之前为空闲复用区。

#### 任务二：初态、队空和队满

初始化时创建一个空闲结点，并令：

```text
front = rear
front->next = front
```

即首尾指针指向同一个空结点。

- 队空：`front==rear`
- 当前已分配链表范围内“队满”：`rear->next==front`

这里的“满”不是操作失败，而是表示没有现成空闲结点；下一次入队需要新建结点扩容。

状态不变量：

> `front` 指向下一出队的有效结点；`rear` 指向下一可写的空闲结点。若 `front==rear`，有效区为空。

#### 任务三：第一个元素入队后的状态

初始时 `front==rear`，两者指向唯一空结点。

入队第一个元素 `x`：

1. 发现 `rear->next==front`，当前没有额外空闲结点；
2. 在 `rear` 后插入一个新的空结点，并保持循环；
3. 把 `x` 写入旧 `rear` 所指结点；
4. 令 `rear=rear->next`，使其重新指向下一空闲结点。

结果：

- `front` 指向保存 `x` 的有效结点；
- `rear` 指向新建的空闲结点；
- 二者不相等；
- `rear->next==front`，当前没有多余空闲结点，但队列非空。

#### 任务四：入队、出队过程

入队：

```text
EnQueue(Q, x):
    if Q.rear->next == Q.front:
        p = new Node
        if p == NULL:
            return false
        p->next = Q.front
        Q.rear->next = p

    Q.rear->data = x
    Q.rear = Q.rear->next
    return true
```

出队：

```text
DeQueue(Q, x):
    if Q.front == Q.rear:
        return false

    x = Q.front->data
    Q.front = Q.front->next
    return true
```

出队时不释放原队首结点。推进 `front` 后，原结点自然落入循环链表的空闲复用区，之后可再次用于入队。

#### 正确性

- 入队只在 `rear` 指向的空闲结点写入数据，再推进 `rear`。
- 若不存在空闲结点，只增加一个结点；插入位置已由 `rear` 给出，不需遍历。
- 出队只读取 `front` 并推进 `front`，不释放结点。
- 每个有效元素保持 FIFO 次序；空闲结点在循环中依次复用。
- 已分配结点数只会在无空闲结点时增加，从不减少，满足“空间只增不减”。

#### 复杂度和实现边界

- 入队：最坏 O(1)，包括一次结点分配和常数次指针修改。
- 出队：O(1)。
- 辅助字段：两个指针，O(1)。
- 若内存分配失败，入队仍须报告失败。
- `rear->next==front` 表示需要扩容，不表示整个抽象队列永久不能入队。
- 必须保持循环链接；新结点插入时不能丢失 `front` 所在的环。

### 3.3应01｜多类型括号匹配｜T11

#### 题目

算术表达式包含圆括号 `()`、方括号 `[]`、花括号 `{}`。以字符 `'\0'` 作为表达式结束符，设计算法判断括号是否配对。

#### 算法

```text
BracketsCheck(str):
    S = empty stack
    i = 0

    while str[i] != '\0':
        ch = str[i]

        if ch in {'(', '[', '{'}:
            Push(S, ch)

        else if ch in {')', ']', '}'}:
            if StackEmpty(S):
                return false

            left = Pop(S)

            if ch == ')' and left != '(':
                return false
            if ch == ']' and left != '[':
                return false
            if ch == '}' and left != '{':
                return false

        i += 1

    return StackEmpty(S)
```

#### 状态与循环不变量

扫描任意前缀后，栈自底向顶恰好保存：

> 该前缀中已经出现、但尚未被右括号匹配的全部左括号，并保持它们的嵌套次序。

因此：

- 新左括号必须压栈；
- 右括号只能匹配最近出现且尚未匹配的左括号，即当前栈顶；
- 若栈空时遇到右括号，说明缺少左括号；
- 若类型不同，说明交叉或异型匹配；
- 扫描结束后栈非空，说明仍有左括号未闭合。

#### 正确性

- 必要性：合法嵌套的最后一个未闭合左括号必然最先被当前右括号关闭，符合 LIFO。
- 充分性：每个右括号都与最近未匹配的同型左括号配对，且最终栈空，故不存在缺失、交叉或多余括号。
- 普通字符不影响括号状态，直接跳过。

#### 复杂度与边界

- 时间：O(n)，每个字符最多处理一次。
- 辅助空间：O(d)，其中 d 是最大括号嵌套深度，最坏 O(n)。
- 空表达式合法。
- 必须在 Pop 前判空。
- 若栈有固定容量，还需在 Push 前判满；容量至少应等于最大嵌套深度。

B. \(i(i-1)/2+j-1\)  
C. \(j(j-1)/2+i\)

  \[

### 3.4选08｜答案 B｜T13

题目：\(n\) 阶下三角矩阵 A 按列优先压缩存入从1开始的一维数组 B。非零元素 \(a_{i,j}\) 与 \(k\) 的关系是（ ）。

### 14.2 教材“思维拓展”：O(1)最小栈

目标：设计一个栈，使 `Push`、`Pop`、`min` 均为最坏 O(1)。

方法：同步双栈。

- 主栈 `S` 保存真实元素。
- 辅助栈 `MinS` 的第 \(k\) 层保存主栈前 \(k\) 个元素的最小值。
- Push(x)：
  - 主栈压入x；
  - 辅助栈压入 `min(x, MinS.top)`。
- Pop：
  - 两个栈同步弹出。
- min：
  - 直接读取 `MinS.top`。

同步不变量：

> 两栈高度始终相同，`MinS[k]` 等于主栈从底到第k层所有元素的最小值。

复杂度：

- Push、Pop、min：最坏 O(1)；
- 辅助空间：O(n)。

AI边界分析：

- 重复最小值必须在辅助栈中重复保存，或另行计数。
- 若只在出现“严格更小”元素时压辅助栈，那么弹出一个重复最小值后可能错误丢失当前最小状态。
- 这是典型的以空间换时间。

## 15. 最终压缩总结

### 15.1 必须掌握

1. 栈、队列都是线性逻辑结构，区别在操作端点限制。
2. 所有顺序栈和循环队列公式必须服从题设的指针语义。
3. 出栈序列用输入指针和栈顶模拟；I/O合法性用前缀栈深判断。
4. 循环队列要用牺牲一格、`size` 或 `tag` 区分空满。
5. 链队通常头删尾插；删除最后结点时首尾状态必须同时维护。
6. 两栈模拟队列时，只有输出栈为空才允许整体转移。
7. 括号、表达式、递归使用栈；BFS、层序、缓冲和公平调度使用队列。
8. 数组地址题先判行/列优先、上下界和元素宽度。
9. 特殊矩阵映射的统一方法是数“目标之前已经存了多少元素”。
10. 稀疏矩阵三元组要与矩阵行数、列数一并保存，且不再具有普通数组的随机存取。

### 15.2 最重要的错误边界

- `top=-1` 与 `top=0` 不能套同一Push语句。
- `front==rear` 本身不能同时解释空与满。
- 链式结构的 O(1) 操作必须区分“已经得到端点”和“需要遍历定位”。
- 中缀转后缀时，操作数直接输出，运算符按优先级和括号状态处理。
- 表达式计算必须遵守题设的 `b op a`，不能擅自交换操作数。
- 矩阵下标从1开始而C数组从0开始时，最终结果通常相差1。
- 来源答案与可见题面不自洽时必须保留冲突，不能为迎合答案改写题面。
