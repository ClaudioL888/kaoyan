# 学习知识库记录时间与周期汇总规范

> 规范建立时间：2026-08-19（Asia/Shanghai，中国标准时间，UTC+08:00）

## 每条记录的必填时间字段

今后每次经用户双重确认后写入的逻辑记录，必须同时满足：

- Markdown 正文包含 `记录时间：YYYY-MM-DD HH:mm:ss +08:00`。
- 元数据使用 ISO 8601：`recorded_at: YYYY-MM-DDTHH:mm:ss+08:00`。
- 同步向根目录 `activity_log.jsonl` 追加一条活动记录。
- 不以文件系统 `mtime` 代替记录时间。
- 真题年份、资料发布日期、核验日期和知识库记录时间是不同字段，不得混用。

## activity_log.jsonl 最小字段

```json
{
  "record_id": "全局唯一记录ID",
  "recorded_at": "2026-08-19T21:00:00+08:00",
  "record_date": "2026-08-19",
  "time_zone": "Asia/Shanghai",
  "time_status": "confirmed-archive 或 backfilled-existing",
  "subject": "math2 / 408.data-structures / 408.computer-organization / 408.operating-systems / 408.computer-networks / english2 / politics",
  "unit_id": "章节或题型模块ID",
  "record_type": "textbook-knowledge / question-method / user-weakness / accepted-review 等",
  "title": "记录标题",
  "summary": "可独立理解的知识点摘要",
  "source_file": "知识库内相对路径",
  "question_refs": ["年份/题型/题号或章节题号"],
  "source_status": "教材核实/真题核实/官方解析核实/独立推导/用户本题等"
}
```

个人薄弱点仍需要真实用户证据；`activity_log.jsonl` 不能绕过双重确认，也不能把候选薄弱点写入。

## 时间窗口

- 日报：运行日之前完整的 1 个自然日，即 `[昨天 00:00, 今天 00:00)`。
- 周报：运行日之前完整的 7 个自然日，即 `[7 天前 00:00, 今天 00:00)`。
- 双周报：运行日之前完整的 14 个自然日，即 `[14 天前 00:00, 今天 00:00)`。
- 统一使用 Asia/Shanghai（中国标准时间，UTC+08:00）；窗口左闭右开，避免边界重复。

## 汇总输出

必须按数二、408、英语二、政治分组；408 再按数据结构、计组、操作系统、计网分组。每条新增知识至少包含：记录时间、章节/模块、知识结论、方法或边界、来源状态、关联题目。有关联题目时优先给出“题号或范围 + 题面摘要 + 解法关键步骤 + 易错点 + 可迁移变式”。

若内容过长，将完整报告写到：

```text
学习知识库/periodic-reports/daily/
学习知识库/periodic-reports/weekly/
学习知识库/periodic-reports/biweekly/
```

对话中只给各科数量、重点和完整文件路径。周期汇总是只读操作，不新增课程知识、不改变掌握度、不触发知识库归档提醒。
